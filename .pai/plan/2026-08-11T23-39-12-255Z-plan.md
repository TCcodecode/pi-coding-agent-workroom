# 高质量 Plan 写作模板与指南

## Goal

让 `plan_save` 产出的每份 plan 都能被**人决策、机器执行、事后验收**。本文件是模板 + 检查清单：写作时复制本文件按节填写，写完用 §Verification 的反例清单自检。

## Current understanding

- Plan 落在 `<workspace>/.pai/plan/`，front matter 记录 `id / status / createdAt / updatedAt / sourceSession`，状态机 `draft → ready → executing → superseded → completed`。
- 本仓库两份历史 plan 的教训：
  - `2026-08-11-plan-execute-mode.md`（产品规格型）：步骤到文件/命令级、有验收标准和测试命令——是范本。
  - `pi-desk-focus` 那份：把大量「已完成的改动」写进 plan——plan 应描述**要做的**，不是 changelog。
- 常见失败模式：目标不可验证、决策没有理由、步骤粒度太大、没有验收、没有退路。

## Decisions and trade-offs

| 决策 | 理由 | 代价 |
|---|---|---|
| 决策节与步骤节分离 | 决策给人评审，步骤给机器/自己执行 | 文档更长，但避免互相污染 |
| 每条决策强制写 trade-off | 后续可反驳、可修改 | 写作成本增加 |
| 步骤强制到文件/命令粒度 | 可勾选、可验收 | 前期调研成本增加 |
| Verification / Risks 独立成节 | 验收与退路不被正文淹没 | 结构固定，小任务略显重 |
| 保留 front matter 生命周期 | 与 plan_save 工具联动，draft→ready 有明确信号 | 需要维护状态 |

## Implementation steps

写 plan 时按此顺序填（每节附好/坏示例）：

1. **Goal** — 一句话 + 可验证标准。
   - 好：`三处状态点颜色语义统一，completed 有独立绿色，light/dark 均覆盖`
   - 坏：`统一状态颜色`
2. **Current understanding** — 只列影响决策的事实，≤5 条；已完成的事一句带过，不写 changelog。
3. **Decisions and trade-offs** — 每条：选了什么 + 为什么 + 代价。
4. **Implementation steps** — 按 Phase / 涉及文件 / 勾选清单（`- [ ]`）。每步可独立执行、可判断完成。
   - 好：`- [ ] 在 electron/planMode.ts 实现 path 校验，拒绝 .. 与 symlink 逃逸`
   - 坏：`- [ ] 实现 plan 模式`
5. **Verification** — 具体命令 + 人工确认项，如 `npm run typecheck` / `vitest run electron/planMode.test.ts` / 人工检查 xxx。
6. **Risks / open questions** — 每条风险至少带应对或回退；不确定的问题单独列，不藏在正文。
7. **Execution handoff** — 下一步谁、做什么、从哪个文件起手；执行者只看这一节也应能开工。

## Verification（本模板的自检清单）

写完草稿后过一遍：

- [ ] Goal 能回答「做完怎么算完」？（有没有量化/可勾选标准）
- [ ] 正文只含「要做的」，没有把已完成工作写成主体？
- [ ] 每条决策都有理由和代价？
- [ ] 每个步骤都能独立执行、粒度到文件/命令？
- [ ] Verification 有具体命令或人工确认项？
- [ ] 每个风险都有应对/回退？
- [ ] 只读 Execution handoff 能独立开工？

## Risks / open questions

- 模板可能过度工程化：一行改动的小任务不需要全部 7 节 → 提供 mini 版（Goal / Steps / Verification / Handoff 四节）。
- open question：用户若已有具体任务，本模板应被替换为针对该任务的真实 plan——确认后立即改写。

## Execution handoff

1. 本文件即模板：复制为新计划，按 §Implementation steps 顺序填写。
2. 若有具体任务：用户提供任务描述，按模板产出第一份真实 plan，用户确认后置 `ready` 再进入执行。
